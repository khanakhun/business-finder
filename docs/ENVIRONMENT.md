# Environment variables

Every variable an app reads is declared once, in `@bf/config` (`packages/config/src`), with a description, a
default (if any) and whether it is secret. The table at the end of this file and `.env.example` are generated
from those schemas — run `pnpm env:doc` / `pnpm env:example` after changing them (CI checks both are current).

## Where values come from

Precedence, highest first:

1. The real process environment (CI, production, `FOO=1 pnpm dev`).
2. `.env.generated` — written by `pnpm infra:up`: connection URLs and ports of the local stack, derived from
   `BF_PORT_OFFSET` and the local credentials. Never edit it; change `.env` and re-run `pnpm infra:up`.
3. `.env` — your local settings and API keys (git-ignored). Start from `cp .env.example .env`.
4. Schema defaults.

An empty value (`FOO=`) counts as unset.

## Checking your setup

```bash
pnpm env:check          # every app
pnpm env:check api      # one app: api | worker | web | sites | intel
```

Each variable is listed with its value (secrets show `(set, hidden)`), followed by a report of anything missing
or invalid. Apps call `loadEnvOrExit(apiEnv)` at startup and exit with code 1 and the same report.

For local development you only need to fill in the required secrets, for example:

```bash
echo "BETTER_AUTH_SECRET=$(openssl rand -base64 32)" >> .env
echo "SECRETS_MASTER_KEY=$(openssl rand -base64 32)" >> .env
echo "INTEL_SHARED_SECRET=$(openssl rand -base64 32)" >> .env
```

## Adding a variable

1. Add it to the right fragment in `packages/config/src/fragments/` (or an app schema in `src/apps/` if only
   one app reads it). Call `.describe()` last, and wrap credentials in `secret(…)` — a test fails if a name that
   looks like a credential is not marked secret, or if any variable lacks a description.
2. Booleans use `booleanFlag(default)` (accepts only `true|false|1|0`); ports use `port(default)`.
3. Run `pnpm env:doc && pnpm env:example` and commit the regenerated files.
4. Never read `process.env` outside `@bf/config`; take the typed object returned by `loadEnv`.

Secrets are never printed by `@bf/config`: reports name the variable but not its value, and `redact()` masks
them for logging.

## Local infrastructure variables

Read only by `scripts/infra.mjs` and Docker Compose (not by apps):

| Variable | Default | Purpose |
|---|---|---|
| `BF_PORT_OFFSET` | `0` | Added to every host port (multiples of 10 up to 70) so several checkouts run side by side. |
| `COMPOSE_PROJECT_NAME` | `bf` | Separates containers and volumes per checkout. |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | `bf` / `bf_local_only` / `bf` | Local database owner. |
| `BF_SITES_RO_PASSWORD` | `bf_sites_ro_local_only` | Password of the read-only `bf_sites_ro` role. |
| `BF_*_PORT` | base port + offset | Host ports, computed by `infra.mjs`; see `scripts/infra/stack.mjs`. |
