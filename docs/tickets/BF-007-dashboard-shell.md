# BF-007 — Next.js dashboard shell, design system and typed API client

## Context
The dashboard (`apps/web`) is a pure client of the API: no business logic, no direct DB access ([ARCHITECTURE.md §3](../ARCHITECTURE.md#3-deployables)). The API (BF-006) emits an OpenAPI document offline. The sales partner (non-developer) and the operator use the dashboard daily, in English and French ([PRD §4](../PRD.md#4-personas)). This ticket creates the shell, the shared UI kit and the generated typed client that all UI tickets build on.

## Goal
A fast, accessible, bilingual dashboard shell with navigation, command palette, theming, error/loading patterns and a generated, typed API client integrated with TanStack Query — ready for feature pages.

## Scope
**In scope**
- `apps/web`: Next.js (latest stable, App Router, React 19, TypeScript strict), Tailwind CSS v4, `next-intl` (EN default, FR) with locale stored in a cookie (no locale prefix in dashboard URLs), `next-themes` (light/dark/system).
- `packages/ui` (`@bf/ui`): shadcn/ui components installed into the package (button, input, textarea, select, combobox, checkbox, switch, label, form (react-hook-form + zod resolver), dialog, sheet, popover, dropdown-menu, tooltip, tabs, badge, card, separator, skeleton, toast (sonner), command (cmdk), table primitives, avatar, progress, scroll-area, breadcrumb, alert) + `DataTable` foundation (TanStack Table v8 with column visibility, sorting, row selection, virtualization hook), `EmptyState`, `ErrorState` (renders problem+json title/detail/traceId), `PageHeader`, `KeyboardShortcut`. Design tokens as CSS variables (brand neutral + accent), typography scale, focus rings.
- Shell layout: collapsible sidebar (Search, Pipeline, Sites, Generation, Outreach → Inbox/Sequences/Templates/Mailboxes, Analytics, Settings), top bar (workspace switcher placeholder, notifications bell placeholder, user menu placeholder, locale switch), breadcrumb, content area, global command palette (`⌘K`/`Ctrl+K`) with navigation commands and a registry so feature tickets can add commands, keyboard shortcuts help (`?`).
- `packages/api-client` (`@bf/api-client`): `openapi.json` (generated by BF-006 `pnpm api:openapi`), types generated with `openapi-typescript`, `createApiClient({ baseUrl, fetch })` using `openapi-fetch` (credentials `include`, problem+json → typed `ApiError`), TanStack Query integration (`openapi-react-query` or thin custom hooks) and a `queryKeys` factory convention; script `pnpm api:codegen` (= openapi + types) and a CI-checkable "stale" mode.
- Providers: TanStack Query (with sensible defaults: retry only idempotent GETs, staleTime 30 s), devtools in development, Toaster, ThemeProvider, IntlProvider.
- Pages: `/` (placeholder dashboard with "API status" card calling `/v1/system/info`), `/settings` placeholder, `not-found`, `error` boundaries, loading skeleton conventions.
- Security headers for the dashboard via `next.config` / middleware: CSP with nonces, `frame-ancestors 'none'`, HSTS (prod), etc. (see security.md §8).
- Playwright set up in `apps/web/e2e` with a smoke test; `@axe-core/playwright` check on the shell.

**Out of scope**
- Auth pages and session handling (→ BF-010). Feature pages (search, business, sites, outreach…). Realtime (→ BF-012).

## Requirements
### Functional
- Navigation, command palette and locale/theme switching work with keyboard only.
- API errors render consistently with `ErrorState` including the `traceId`.
### Non-functional
- LCP < 2.5 s on the shell (production build, local); no layout shift on theme switch.
- WCAG 2.1 AA for the shell (axe: zero serious/critical violations).
- Client bundle for the shell < 200 kB gzipped (excluding devtools).

## Design
```
apps/web/
├── src/app/(dashboard)/layout.tsx       # shell
├── src/app/(dashboard)/page.tsx         # home placeholder
├── src/app/(dashboard)/settings/page.tsx
├── src/components/shell/{sidebar,topbar,command-palette,shortcuts}.tsx
├── src/lib/{api.ts, query-keys.ts, commands.ts}
├── src/i18n/{request.ts, messages/en.json, messages/fr.json}
├── middleware.ts                         # CSP nonce, locale cookie
└── e2e/{smoke.spec.ts, a11y.spec.ts}
packages/ui/src/{components/*, data-table/*, styles/tokens.css, index.ts}
packages/api-client/{openapi.json, src/{schema.d.ts, client.ts, query.ts}}
```
- Command registry pattern: `registerCommand({ id, label: msgKey, shortcut?, run })` collected via a React context; features register on mount.
- All strings via `next-intl` message keys; ESLint/Biome rule or a test that fails on hard-coded user-facing strings in components (pragmatic: test scanning JSX text nodes in `src/components` for non-key literals).

## Implementation plan
1. Verify current Next.js, Tailwind v4, shadcn/ui (monorepo setup), next-intl (App Router without locale prefix), openapi-typescript/openapi-fetch docs.
2. Create `@bf/ui` with shadcn components + tokens; Storybook is optional — prefer a `/dev/ui` route (dev-only) showcasing components.
3. Create `@bf/api-client` and codegen script.
4. Build the shell, providers, command palette, i18n, theming.
5. Security headers + CSP nonces.
6. Playwright smoke + a11y tests.

## Testing
- Unit (Vitest + Testing Library): `ErrorState` renders problem fields; command registry; `ApiError` parsing from problem+json.
- E2E: shell loads; sidebar navigation; ⌘K opens palette and navigates; locale switch changes visible strings; theme toggle; API status card shows version (API running in E2E environment).
- Accessibility: axe on `/` and `/settings`.

## Acceptance criteria
- [ ] `pnpm --filter @bf/web dev` shows the shell; navigation and command palette work by keyboard.
- [ ] EN/FR switch persists via cookie; all shell strings translated.
- [ ] `pnpm api:codegen` regenerates the client from the API; home page shows API version via the typed client.
- [ ] Problem+json errors render with trace id.
- [ ] Axe: zero serious/critical violations on shell pages; Playwright smoke passes in CI-like run.
- [ ] CSP with nonces active in production build (verified by response headers).
